### 3.5 真实缺陷修复记录

开发过程中的验证不是走形式——以下缺陷是**由测试失败暴露并修复**的，
每一项都留下了回归测试：

| 编号 | 缺陷 | 表现 | 修复 | 回归用例 |
| --- | --- | --- | --- | --- |
| 1 | 函数识别把控制流语句当作函数 | `if (a > 0) {` 被识别为名为 `if` 的函数，污染函数数量、最长函数、复杂度等全部结构指标 | 引入保留字黑名单过滤 | 「控制流语句不得被误判为函数」 |
| 2 | 函数起始行号少算一行 | 匹配模式带前置空白，`match.index` 指向上一行的换行符 | 换算行号前先剔除匹配文本的前导空白 | 「模式含前置空白时行号不得偏移」 |
| 3 | 可维护性指数恒为常数 | 三元运算符优先级低于加减法，整个表达式退化为「三选一」，输出与规模无关的固定值 15 | 为每个因子显式加括号 | 「可维护性指数随规模增长而下降」 |
| 4 | 嵌套深度被调用括号污染 | `Promise.all(urls.map(x => …))` 的圆括号被计入嵌套，规范代码误报「嵌套过深」 | 只统计语句块花括号 | 「只统计语句块花括号，调用括号不计入」 |
| 5 | SQL 拼接漏报 | 模式用 `[^"']` 排除引号，而 SQL 片段内含引号，导致无法匹配 | 改为「SQL 关键字后紧跟拼接/插值」的行内检测，不依赖字符串边界 | 「SQL 拼接与命令注入」 |
| 6 | 浮点比较被过滤器误杀 | 排除「与 0 比较」的正则 `0\b` 会匹配 `0.3` 中的 `0` | 增加负向先行断言 `(?![.\d])` | 「浮点比较」检出用例 |
| 7 | 除零守卫误判 | 只检查当前行，导致函数内存在无关的 `if (a == b)` 时漏报；后续改为窗口回溯又过度放行 | 要求出现与 0 的比较、取反判断或 `Math.max` 兜底 | 「带守卫的除法与字符串中的比较符」 |
| 8 | 占位符正则误锚定 | `^(?:…|your|…)$` 全串锚定，`your_api_key_here` 被判为真实凭据（误报） | 改为「以占位特征开头」，整体由 x/\*/ 组成的才要求占满 | 「硬编码凭据（含带前缀的常见命名）」 |
| 9 | 词边界导致凭据漏报 | `\bpassword\b` 在 `DB_PASSWORD` 中无词首边界（下划线是单词字符），大量漏报 | 改为「标识符以敏感词结尾」的匹配方式 | 同上一项 |
| 10 | 空行统计把注释块当空行 | 基于剥离注释后的文本统计，连续注释行被判为「连续多个空行」 | 改用原始行统计 | 「连续多个空行」检出用例 |
| 11 | 思维链模型输出截断 | `deepseek-flash` 的推理 token 占用输出预算，4096 上限下 4 次调用有 3 次正文为空/不完整，错误信息却是模糊的「JSON 解析失败」 | 提高默认上限至 16000；检测 `finish_reason` 与 `reasoning_tokens` 并给出可操作诊断；语义错误不重试 | 「输出被 max_tokens 截断时给出可操作的精确诊断」 |
| 12 | 雷达图轴标签被裁切 | 画布 viewBox 与图形等宽，左右两侧标签的 `getBBox()` 超出边界（右溢至 287 > 260，左溢至 −28），肉眼可见文字被切断 | 画布改为非对称宽高比 340×260，为标签预留横向余量；同时把 SVG 表现属性中无效的 `var(--sans)` 换成具体字体族 | 元素级截图 + `getBBox()` 边界校验 |
| 13 | 离线模式仍调用大模型 | `--no-llm` 只关闭了多角色评审，修复建议生成仍走真实大模型，导致「离线零调用」承诺被破坏，no-llm 审查耗时从毫秒级飙到 33 秒 | 为修复建议生成增加 `allowLlm` 开关，`useLlm=false` 时强制走内置模板 | 「离线模式下修复建议使用内置模板且零大模型调用」 |

| 收益 | 说明 |
| --- | --- |
| 确定性 | 同一输入产出同一结论，断言可以精确到条数与字段 |
| 零成本 | 不消耗 API 额度，CI 中可高频运行 |
| 零网络 | 断网、内网、评审现场均可执行 |
| 隔离性 | 大模型侧的不确定性不会掩盖引擎自身的回归问题 |

真实大模型调用则通过 `docs/sample-report.*` 的端到端记录与本节 3.3 节的实测数据覆盖。

### 7.2 测试设计原则

1. **回归优先**：每一个被修复的缺陷都必须留下一条会因该缺陷重现而失败的用例
   （见 3.5 节的 13 项记录）。
2. **约束而非实现**：断言写在契约层面（例如「干净代码零告警」「σ 随规模单调下降」），
   而不是绑定具体实现细节，使测试不阻碍合理重构。
3. **边界与反例并重**：既验证「能检出」，也验证「不该检出时不检出」——
   后者对代码审查工具尤为重要，因为误报会直接摧毁使用者对工具的信任。
4. **危险路径必测**：路径穿越、XSS 转义、请求体超限、密钥脱敏等安全相关行为均有独立用例。
