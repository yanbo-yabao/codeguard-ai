## 一、依赖清单

### 1.1 运行时第三方依赖

**无。**

本项目在设计上有意做到运行时零第三方依赖，全部能力基于 Node.js 内置模块实现：

| 用途 | 使用的内置模块 | 引入位置 |
| --- | --- | --- |
| HTTP 服务与路由 | `http` | `src/core/http/`、`src/server.js` |
| 文件与路径处理 | `fs`、`path` | `src/config/`、`src/core/storage.js`、`src/analyzers/` |
| 哈希与指纹 | `crypto` | `src/core/utils.js` |
| 大模型网络请求 | 全局 `fetch`（Node 18.17+ 内置） | `src/agents/llm-client.js` |
| 随机标识与并发控制 | 全局 `Promise`、`AbortController` | `src/core/utils.js`、`src/agents/llm-client.js` |
| 测试框架 | `node:test`、`node:assert` | `test/*.test.js` |

`package.json` 中：

```json
{
  "dependencies": {},
  "devDependencies": {},
  "engines": { "node": ">=18.17.0" }
}
```

**由此带来的收益**

| 收益 | 说明 |
| --- | --- |
| 安装必定成功 | `npm install` 不访问 npm registry，不存在网络超时、镜像失效、版本冲突导致的安装失败 |
| 离线完整可用 | 评审现场、内网机房无需外网；未配置大模型密钥时规则引擎功能同样完整 |
| 无供应链风险 | 不存在第三方包的已知漏洞、许可证不兼容或恶意投毒风险 |
| 体积与启动 | 无 `node_modules`，冷启动与内存占用极低 |

**代价与应对**：需要自行实现路由、dotenv 解析、SVG 图表等基础设施。
这些实现均已配套单元测试（见 [测试与验证报告](测试与验证报告.md)）。

## 二、环境变量模板

仓库根目录提供完整模板 [`.env.example`](../.env.example)。使用方式：

```bash
# Linux / macOS
cp .env.example .env

# Windows PowerShell
Copy-Item .env.example .env

# Windows CMD
copy .env.example .env
```

> **`.env` 已被 `.gitignore` 排除**，不会进入版本库，可安全填写密钥。
> 项目启动时会自动读取该文件（已存在于系统环境的同名变量优先，不会被覆盖）。

### 2.1 服务运行参数

| 变量名 | 类型 | 默认值 | 取值范围 | 说明 |
| --- | --- | --- | --- | --- |
| `PORT` | number | `8848` | 1~65535 | HTTP 监听端口 |
| `HOST` | string | `127.0.0.1` | IP 地址 | 监听地址。`127.0.0.1` 仅本机可访问；局域网演示改为 `0.0.0.0` |
| `NODE_ENV` | string | `development` | `development` / `production` / `test` | 运行环境标识，会写入配置快照 |
| `LOG_LEVEL` | string | `info` | `debug` / `info` / `warn` / `error` / `silent` | 日志输出级别，低于该级别的日志被丢弃 |
| `LOG_FORMAT` | string | `pretty` | `pretty` / `json` | `pretty` 带 ANSI 颜色适合本地；`json` 适合容器日志采集 |
| `MAX_BODY_BYTES` | number | `5242880` | ≥ 1024 | 单次 HTTP 请求体上限（字节），超限返回 413 |

### 2.2 大模型服务参数

| 变量名 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `LLM_PROVIDER` | enum | `deepseek` | `deepseek` / `openai-compatible` / `mock` |
| `DEEPSEEK_API_KEY` | string | 空 | DeepSeek 密钥，[申请地址](https://platform.deepseek.com/api_keys) |
| `DEEPSEEK_BASE_URL` | url | `https://api.deepseek.com` | 接口根地址，末尾无需 `/v1` 或 `/` |
| `DEEPSEEK_MODEL` | string | `deepseek-flash` | 模型名。可用 `GET {BASE_URL}/models` 查询账号可用列表 |
| `OPENAI_COMPATIBLE_API_KEY` | string | 空 | `LLM_PROVIDER=openai-compatible` 时生效 |
| `OPENAI_COMPATIBLE_BASE_URL` | url | 空 | 兼容后端的根地址，需包含版本路径（如 `/v1`） |
| `OPENAI_COMPATIBLE_MODEL` | string | 空 | 兼容后端的模型名 |

**三种提供者的行为差异**

| `LLM_PROVIDER` | 是否必需密钥 | 适用场景 |
| --- | --- | --- |
| `deepseek` | 是 | 使用 DeepSeek 官方接口；本项目实测验证的配置 |
| `openai-compatible` | 是 | 任意兼容 OpenAI `/chat/completions` 协议的服务 |
| `mock` | 否 | 离线演示、单元测试、断网环境；输出确定性结论 |

`openai-compatible` 的常见后端取值：

| 服务 | `OPENAI_COMPATIBLE_BASE_URL` | 备注 |
| --- | --- | --- |
| Moonshot Kimi | `https://api.moonshot.cn/v1` | 模型名如 `moonshot-v1-8k` |
| 火山方舟 | `https://ark.cn-beijing.volces.com/api/v3` | 模型名填接入点 ID |
| 本地 Ollama | `http://127.0.0.1:11434/v1` | 模型名如 `qwen2.5:7b` |
| 本地 vLLM | `http://127.0.0.1:8000/v1` | 模型名填部署时的模型路径 |
| 阿里通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 模型名如 `qwen-plus` |

### 2.3 审查引擎参数

| 变量名 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `REVIEW_ENABLE_LLM` | boolean | `true` | 关闭后仅运行规则引擎，完全离线 |
| `REVIEW_TEMPERATURE` | number | `0.2` | 采样温度，范围 0~2。代码审查建议 ≤ 0.3 以保证结论稳定 |
| `REVIEW_MAX_TOKENS` | number | `16000` | 单次调用最大输出 token |
| `REVIEW_CONCURRENCY` | number | `2` | 大模型并发度（同时发起几个角色请求） |
| `REVIEW_TIMEOUT_MS` | number | `120000` | 单次请求超时（毫秒） |
| `REVIEW_MAX_RETRIES` | number | `2` | 超时与 5xx 的可重试次数；语义错误（截断）不重试 |
| `REVIEW_MAX_LINES` | number | `1200` | 送审最大行数，超出部分截断并告警 |
| `REVIEW_CHUNK_LINES` | number | `400` | 分段送审时每段行数，分段会尽量对齐到空行 |

> **重要提示**：`deepseek-flash` 等含思维链的模型会把推理过程计入输出预算
> （响应中的 `completion_tokens_details.reasoning_tokens`）。若 `REVIEW_MAX_TOKENS`
> 设置过小，正文会被截断，表现为「JSON 解析失败」。**建议不低于 16000**。
> 该场景下的错误信息会明确给出 `max_tokens` 与推理 token 占用，便于定位。

**参数调优建议**

| 现象 | 调整 |
| --- | --- |
| 单次审查太慢 | 减小 `REVIEW_CHUNK_LINES`；减小 `REVIEW_MAX_TOKENS`（但保持 ≥ 16000 以免截断） |
| 触发服务端限流（429） | 减小 `REVIEW_CONCURRENCY` 到 1 |
| 请求频繁超时 | 增大 `REVIEW_TIMEOUT_MS`；增大 `REVIEW_MAX_RETRIES` |
| 部分角色失败 | 查看响应的 `llm.errors`；确认模型名与密钥权限 |
| 想降低成本 | 关闭 `includeFixes`、减少 `fixLimit`、只启用必要的 `roles` |

### 2.4 存储与集成参数

| 变量名 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `DATA_DIR` | path | `data` | 评审记录存放目录，相对路径以项目根为基准 |
| `KEEP_REPORT_FILES` | boolean | `true` | 是否保留导出过的报告文件 |
| `GITEE_ACCESS_TOKEN` | string | 空 | Gitee 私人令牌，仅需 `projects` 只读权限。留空则关闭该能力 |
| `GITEE_API_BASE` | url | `https://gitee.com/api/v5` | Gitee 开放接口根地址 |

**布尔值的书写方式**：`true` / `false`，同时接受 `1` / `0` / `yes` / `no` / `on` / `off`（不区分大小写）。

## 三、配置的加载与优先级

启动时的配置解析流程：

```text
进程已有的环境变量  ──┐
                      ├──► 合并（系统环境变量优先，不被 .env 覆盖）
项目根目录 .env 文件 ──┘
                              │
                              ▼
                     类型转换 + 合法性校验 + 默认值兜底
                              │
                              ▼
                       结构化 config 对象
                    （同时对密钥做掩码，供 /api/meta/config 下发）
```

| 优先级 | 来源 | 说明 |
| ---: | --- | --- |
| 1（最高） | 进程环境变量 | 例如 `docker run -e`、CI 的 secrets、shell 中 `export` |
| 2 | 项目根目录 `.env` | 仅在系统环境变量未定义该键时注入 |
| 3（最低） | 代码内置默认值 | 见上文各表格的「默认值」列 |

**实践建议**

- 本地开发：把配置写在 `.env`，方便反复调整；
- Docker 部署：用 `docker-compose.yml` 的 `environment` 或 `-e` 传参，不把密钥打进镜像；
- CI：使用平台的 Secrets 机制注入 `DEEPSEEK_API_KEY`，或直接用 `LLM_PROVIDER=mock` 避免消耗额度。

## 五、常见配置问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `npm run doctor` 显示大模型为感叹号 | 密钥缺失或仍是占位符 | 检查 `.env` 存在且 `DEEPSEEK_API_KEY` 已填真实值 |
| 返回 502 `LLM_ERROR` | 密钥无效 / 模型名不存在 / 余额不足 | 用 `GET {BASE_URL}/models` 确认模型名；核对密钥权限 |
| 报「输出被 max_tokens 截断」 | 思维链模型推理占用输出预算 | 将 `REVIEW_MAX_TOKENS` 调到 16000 以上 |
| 局域网其他设备无法访问 | `HOST` 仍为本机回环地址 | 改为 `HOST=0.0.0.0` 并检查防火墙 |
| 返回 413 | 请求体超过 `MAX_BODY_BYTES` | 调大该值，或改用文件上传方式分批提交 |
| 数据目录不可写 | 权限不足或路径不存在 | 检查 `DATA_DIR` 权限；容器中确认卷已挂载 |
| 日志中文乱码（Windows） | 终端代码页非 UTF-8 | 执行 `chcp 65001`，或改用 `LOG_FORMAT=json` |
