## 二、逐项详细说明

### 2.1 托管平台：Gitee

| 项 | 说明 |
| --- | --- |
| 仓库形态 | 标准 Git 仓库，含完整提交历史与分支结构 |
| 可见性 | 按赛题要求设为 **Public**（公开仓库），无需额外授权即可访问 |
| 推送支持 | 提供一键推送脚本 `tools/push-to-gitee.ps1`，自动完成远程地址配置与首次推送 |
| 平台适配 | 提供 Gitee Go 流水线配置 `.workflow/codeguard.yml`，与仓库根目录的 CI 配置配套 |
| 访问入口 | 【待填写：仓库地址，例如 `https://gitee.com/xxx/codeguard-ai`】 |

无需跳转。

### 2.2 代码规范

**结构清晰**

采用四层架构，依赖方向严格自上而下，任一层可独立替换：

| 层次 | 目录 | 模块数 |
| --- | --- | ---: |
| 接入层 | `src/routes/`、`web/`、`bin/` | 6 |
| 服务层 | `src/services/`、`src/core/http/` | 7 |
| 引擎层 | `src/analyzers/`、`src/agents/` | 9 |
| 支撑层 | `src/config/`、`src/core/` | 7 |

模块职责与路径的完整映射见 [README 2.3 节](../README.md#23-模块说明)。

**有效注释**

本项目的注释遵循「解释为什么，而非复述代码是什么」的原则，侧重记录设计决策与踩坑经验。
示例（节选自 `src/analyzers/languages.js`）：

```js
/**
 * 将字符串字面量替换为等量空格，得到「纯语法」文本
 * ---------------------------------------------------------------------------
 * 用途：面向运算符与关键字的规则（松散相等、浮点比较、花括号配对等）必须在
 * **不含字符串内容** 的文本上匹配，否则 `if (a === "==")` 之类的写法会被误报。
 * 设计：先由 splitCodeAndComments 抹掉注释，再调用本函数抹掉字符串，两阶段互不干扰。
 * @param {string} code 已剥离注释的代码
 * @param {object} profile 语言画像
 * @returns {string} 换行保留、字符串被空格替换的文本
 */
```

这类注释在项目中大量存在，用于避免后续维护者「好心改坏」——
例如 `src/analyzers/metrics.js` 中关于三元运算符优先级的警告，
正是由一次真实的线上缺陷（可维护性指数恒为常数）换来的。

**遵循主流规范**

| 规范项 | 采用标准 | 强制方式 |
| --- | --- | --- |
| 缩进 | 2 空格（JS/JSON/YAML/HTML/CSS），Tab（Makefile） | `.editorconfig` |
| 换行符 | LF | `.editorconfig` |
| 行尾 | 去除多余空白，文件末尾保留一个换行 | `.editorconfig` + 内置规则 `STY005` |
| 字符编码 | UTF-8 | `.editorconfig` |
| 命名 | 变量/函数小驼峰、类大驼峰、常量全大写下划线 | JSDoc `@param` / `@returns` 全量标注 |
| 严格模式 | 所有源码文件首行 `'use strict';` | 逐文件声明，共 25 处 |
| 模块系统 | CommonJS（`require` / `module.exports`） | 统一风格，无混用 |
| 错误处理 | 自定义错误体系 + 稳定错误码，禁止裸抛字符串 | `src/core/errors.js` |
| 单文件规模 | 上限 800 行（违反时被自身规则 `MNT006` 检出） | 本项目对自身运行审查，结果见下文 2.6 节 |

**自我审查（dogfooding）**

本项目可用自身的审查引擎检查自身代码，验证规范落地情况：

```bash
node bin/codeguard.js review src/ --no-llm
```

这也是最直接的「吃自己的狗粮」验证：如果规则引擎会对自己产生大量误报，
说明规则设计中存在系统性问题。

| 用途 | 内置模块 |
| --- | --- |

建议按以下顺序验收，约 5 分钟即可覆盖全部要求：

```bash
# ① 看提交历史（验证要求：Git 记录）
git log --oneline --graph | head -20

# ② 看环境配置模板（验证要求：环境变量模板）
cat .env.example

# ③ 看依赖清单（验证要求：依赖清单 —— 运行时零第三方依赖）
cat package.json | grep -A2 dependencies

# ④ 一键运行（验证要求：可运行性）
npm install && npm test          # 预期 98 个用例全部通过
npm start                        # 启动服务

# ⑤ 浏览器打开 http://127.0.0.1:8848/
#    点击「示例样本」→ 选中任一示例 → 点击「开始智能审查」
#    观察：综合得分仪表盘、五维雷达图、问题清单、修复建议、代码度量、评审历史

# ⑥ 验证零误报（本项目的核心质量约束）
node bin/codeguard.js review examples/clean-sample.js --no-llm
#    预期：100 分 / 等级 S / 0 个问题
```
