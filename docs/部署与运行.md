# 部署与运行指南

本文覆盖从零开始的全部部署路径：本地开发、局域网演示、Docker 容器化、以及接入 CI 流水线。

---

## 一、环境要求

| 项 | 最低要求 | 推荐 | 说明 |
| --- | --- | --- | --- |
| Node.js | **18.17.0** | 20 LTS 或 22 LTS | 需要内置 `fetch`（18.0+）与 `node:test`（18.0+） |
| 内存 | 256 MB | 512 MB | 纯 JS 实现，内存占用极低 |
| 磁盘 | 50 MB | 200 MB | 主要占用为评审记录 |
| 网络 | **可选** | 可访问大模型接口 | 仅启用大模型评审时需要；规则引擎完全离线 |
| 容器运行时 | 可选 | Docker 24+ | 仅容器化部署时需要 |

验证 Node 版本：

```bash
node --version    # 必须 >= v18.17.0
```

## 二、本地开发部署

### 2.1 获取代码

```bash
git clone <仓库地址>
cd codeguard-ai
```

### 2.2 安装依赖

```bash
npm install
```

> **说明**：本项目运行时**零第三方依赖**，上述命令不会下载任何包，也不会访问 npm registry。
> `package.json` 中 `dependencies` 与 `devDependencies` 均为空对象。这一步保留是为了
> 兼容标准部署流程与未来的可选扩展。

### 2.3 配置环境变量

```bash
# Linux / macOS
cp .env.example .env

# Windows PowerShell
Copy-Item .env.example .env

# Windows CMD
copy .env.example .env
```

编辑 `.env`，至少填写大模型密钥（不填则自动进入纯规则引擎模式）：

```ini
LLM_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-你的密钥
DEEPSEEK_MODEL=deepseek-flash
```

> 可用模型可通过 `GET https://api.deepseek.com/models` 查询。本项目实测可用：
> `deepseek-flash`、`deepseek-v4-pro`。

### 2.4 启动服务

```bash
npm start
```

看到启动横幅即表示成功：

```text
  CodeGuard AI  v1.0.0   ·   面向开发者的 AI 代码审查 Agent

  评审台    http://127.0.0.1:8848/
  健康检查  http://127.0.0.1:8848/api/meta/health
```

浏览器打开 `http://127.0.0.1:8848/` 即可使用。

### 2.5 环境自检

```bash
npm run doctor
```

自检会逐项确认：Node 版本、`.env` 是否存在、大模型是否可用、内置 `fetch` 是否就绪、
数据目录是否可写，并打印支持的语言清单与运行配置。

### 2.6 运行测试

```bash
npm test
```

预期输出 `tests 97 / pass 97 / fail 0`。测试使用离线模拟器作为大模型后端，
**不需要网络与密钥**。

## 三、局域网演示部署

评审现场常用：一台机器启动服务，其他设备（手机、平板、评委笔记本）通过局域网访问。

```ini
# .env
HOST=0.0.0.0
PORT=8848
```

```bash
npm start
```

在服务端机器查询本机局域网 IP：

```powershell
# Windows
ipconfig | Select-String "IPv4"
```

```bash
# Linux / macOS
ip addr show | grep "inet "      # 或 ifconfig | grep "inet "
```

其他设备访问 `http://<局域网IP>:8848/`。

**排查清单**

| 现象 | 原因与处理 |
| --- | --- |
| 其他设备打不开 | 检查服务端防火墙是否放行 8848 端口 |
| 打开但接口报错 | 确认 `HOST` 已改为 `0.0.0.0` 并重启服务 |
| 页面前端加载但审查无响应 | 浏览器控制台查看 `/api/*` 请求状态码 |

## 四、Docker 容器化部署

### 4.1 使用 docker compose（推荐）

```bash
cd docker
docker compose up -d --build
```

自定义端口与密钥：

```bash
PORT=9000 DEEPSEEK_API_KEY=sk-xxx docker compose up -d
```

### 4.2 直接使用 Dockerfile

```bash
docker build -t codeguard-ai -f docker/Dockerfile .

docker run -d \
  --name codeguard \
  -p 8848:8848 \
  -e DEEPSEEK_API_KEY=sk-xxx \
  -e LLM_PROVIDER=deepseek \
  -e DEEPSEEK_MODEL=deepseek-flash \
  -v codeguard-data:/app/data \
  codeguard-ai
```

### 4.3 数据持久化

评审记录存放在容器内 `/app/data`，通过命名卷 `codeguard-data` 持久化。
查看与清理：

```bash
docker volume inspect codeguard-data
docker compose down          # 停止但保留数据
docker compose down -v       # 停止并删除数据（谨慎使用）
```

### 4.4 容器日志

```bash
docker logs -f codeguard

# 生产环境建议改用 JSON 日志便于采集
docker run -e LOG_FORMAT=json -e LOG_LEVEL=info ...
```

### 4.5 健康检查

`docker-compose.yml` 已配置容器健康检查，每 30 秒请求一次 `/api/meta/health`：

```bash
docker inspect --format='{{json .State.Health}}' codeguard
```

## 五、接入 CI 流水线

CLI 的退出码约定使其可直接作为质量门禁：

| 退出码 | 含义 |
| --- | --- |
| `0` | 无阻断/严重级问题，允许合入 |
| `1` | 存在 blocker 或 critical 级问题，阻止合入 |
| `2` | 参数错误或输入为空 |

### 5.1 Gitee Go

在仓库根目录新建 `.workflow/codeguard.yml`：

```yaml
name: CodeGuard 代码审查
displayName: '代码质量门禁'

triggers:
  push:
    branches:
      include:
        - master
        - main
        - 'feature/**'
  pull_request:
    branches:
      include:
        - master
        - main

variables:
  GLOBAL:
    LLM_PROVIDER: mock        # CI 中不消耗真实额度；如需大模型审查，改为 deepseek 并配置密钥变量
    REPORT_PATH: codeguard-report.md

stages:
  - stage:
      name: review
      displayName: '执行代码审查'
      steps:
        - step: build@node
          name: node
          displayName: 'Node 环境与审查'
          nodeVersion: 20
          commands:
            - npm install
            - npm test
            - node bin/codeguard.js review src/ --min-severity major --format markdown --out $REPORT_PATH
        - step: publish@artifact
          name: artifact
          displayName: '上传审查报告'
          artifactName: codeguard-report
          artifactPath: $REPORT_PATH
```

### 5.2 GitHub Actions

```yaml
name: CodeGuard

on: [push, pull_request]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install
      - run: npm test
      - name: 代码审查（规则引擎 + 大模型）
        env:
          LLM_PROVIDER: deepseek
          DEEPSEEK_API_KEY: ${{ secrets.DEEPSEEK_API_KEY }}
          DEEPSEEK_MODEL: deepseek-flash
        run: node bin/codeguard.js review src/ --min-severity major --format markdown --out report.md
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: codeguard-report
          path: report.md
```

### 5.3 本地 Git 钩子（提交前拦截）

`.git/hooks/pre-commit`：

```bash
#!/bin/sh
# 仅审查本次暂存的改动，存在阻断级问题时阻止提交
git diff --cached --unified=0 | node bin/codeguard.js review - --no-llm --min-severity critical
```

```bash
chmod +x .git/hooks/pre-commit
```

## 六、生产环境建议

| 项 | 建议 |
| --- | --- |
| 反向代理 | 前置 Nginx 处理 TLS、压缩与限流；本服务只监听内网地址 |
| 访问控制 | 当前版本未内置鉴权，暴露到公网前请在反向代理层加 Basic Auth 或 IP 白名单 |
| 日志 | `LOG_FORMAT=json` 便于采集；建议 `LOG_LEVEL=info` |
| 数据清理 | 定期清理 `data/reviews/`；也可通过 `DELETE /api/reviews/:id` 单条删除 |
| 进程管理 | 使用 `pm2`、`systemd` 或容器编排守护进程，配合 `/api/meta/health` 做存活探针 |
| 并发 | 单实例足以支撑小型团队；大模型调用并发由 `REVIEW_CONCURRENCY` 控制，避免触发服务端限流 |
| 密钥管理 | 生产环境建议用 Docker secret 或 KMS 注入，不要把密钥写入镜像 |

### systemd 单元示例

```ini
[Unit]
Description=CodeGuard AI 代码审查服务
After=network.target

[Service]
Type=simple
User=codeguard
WorkingDirectory=/opt/codeguard-ai
EnvironmentFile=/opt/codeguard-ai/.env
ExecStart=/usr/bin/node src/server.js
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target
```

## 七、升级与回滚

```bash
# 升级
git pull
npm install          # 零依赖，通常无变化
npm test             # 确认测试通过
# 重启服务（systemd）
sudo systemctl restart codeguard

# 回滚
git checkout <上一个稳定 tag>
sudo systemctl restart codeguard
```

历史评审记录与代码版本无关，升级不会影响已有 `data/` 目录。

## 八、故障排查

<details>
<summary><b>启动报 EADDRINUSE（端口被占用）</b></summary>

```bash
# 查看占用进程
# Windows
netstat -ano | findstr :8848
# Linux / macOS
lsof -i :8848
```

处理方式：终止占用进程，或修改 `.env` 中的 `PORT`，或临时指定
`node bin/codeguard.js serve --port 9000`。
</details>

<details>
<summary><b>npm run doctor 显示「大模型连接」为感叹号</b></summary>

说明未检测到可用的密钥。检查：

1. `.env` 是否存在于项目根目录（不是 `.env.example`）；
2. `DEEPSEEK_API_KEY` 是否仍为模板占位符 `sk-xxxx…`；
3. `LLM_PROVIDER` 的值与所填密钥是否匹配。

此项为警告而非错误——不配置密钥时规则引擎仍完整可用。
</details>

<details>
<summary><b>审查报「模型输出被 max_tokens 截断」</b></summary>

`deepseek-flash` 等含思维链的模型会把推理过程计入输出预算。若 `REVIEW_MAX_TOKENS`
偏小，正文会被截断。处理：把 `REVIEW_MAX_TOKENS` 调到 `16000` 以上
（`.env.example` 的默认值已为 16000）。
</details>

<details>
<summary><b>审查耗时很长或部分角色失败</b></summary>

1. 调小 `REVIEW_CHUNK_LINES`（默认 400），减小单次送审体积；
2. 调小 `REVIEW_CONCURRENCY`（默认 2）以规避服务端限流；
3. 调大 `REVIEW_TIMEOUT_MS`（默认 120000）；
4. 先用 `--no-llm` 拿到规则引擎结论，再单独排查大模型链路。
</details>

<details>
<summary><b>数据目录不可写（doctor 报错）</b></summary>

容器部署时检查卷挂载权限；本地部署时检查 `DATA_DIR` 指向的目录是否存在且当前用户可写。
</details>
